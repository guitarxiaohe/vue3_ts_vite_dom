# Login Entrance Animation Design

## 背景

当前登录页已经具备稳定的最终布局：

- 左侧为品牌插画与四个角色
- 右侧为登录表单
- 角色已有鼠标跟随、眨眼、输入联动等交互

本次需求不是重做版式，而是在进入登录页时增加一段一次性的入场动画，让页面从“全屏角色插画”过渡到“左右各占 50% 的登录页最终态”。

## 目标

- 首屏先展示全屏插画前景
- 两个主拉小人一起从最右侧把前景层往左拉开
- 前景层拉开后露出右侧登录表单，最终停在 50 / 50 布局
- 拉开结束后，两个主拉小人做一次轻微“跳回原位”的回弹，恢复到正常站姿
- 动画结束后，保留现有登录页中的角色轻交互，不重复播放强入场动画

## 非目标

- 不重做现有登录页的整体结构
- 不修改登录业务流程、接口、表单校验逻辑
- 不新增复杂 SVG 形变系统
- 不让入场动画循环播放

## 用户体验定义

用户第一次进入登录页时，应先看到一张完整的紫色品牌插画。随后，两个靠近右侧边界的角色一起发力，把右侧前景层从最右边向左拉开，像拉开一层幕布或面板。随着前景层被拉开，右侧登录表单逐步露出并淡入。完成拉开后，两个角色做一次短促回弹，回到当前登录页中的正常姿态。

最终状态必须清晰稳定：

- 左侧插画占 50%
- 右侧表单占 50%
- 小人回到正常站姿
- 现有眼睛跟随、眨眼和输入态交互继续可用

## 方案对比

### 方案 1：在现有页面上增加可拉开的前景覆盖层

做法：

- 保留现有登录页最终态 DOM
- 在最上层增加一个 `login-entrance-overlay`
- overlay 初始覆盖全屏，内部放置全屏插画与两个主拉小人的动作状态
- 通过 GSAP timeline 驱动 overlay 从最右向左收起，露出下层的最终态页面

优点：

- 与现有登录页结构最兼容
- 动画和最终态分层清晰
- 风险最低，最容易控制结束后的稳定状态

缺点：

- 需要维护一层入场专用前景态

### 方案 2：让整块插画区域整体平移

做法：

- 不做覆盖层，直接推动现有左侧插画区移动

优点：

- 实现简单

缺点：

- 不符合“从最右边往左拉开”的动作语义
- 更像页面滑动，而不是角色拉开前景

### 方案 3：使用 SVG/path 形变表现拉扯边缘

做法：

- 用 SVG 或路径形变做右侧边界的拉扯和弹性

优点：

- 表现力更强

缺点：

- 实现复杂度高
- 与当前页面结构整合成本高
- 超出本次最小实现范围

## 选定方案

采用方案 1。

原因：

- 最贴合“两个小人一起拉开右侧前景”的需求
- 不破坏现有登录页最终布局和业务逻辑
- 能清楚控制动画结束后的稳定状态
- 便于做移动端降级和 reduced motion 处理

结构原则：

- overlay 收起后不销毁最终态 DOM
- overlay 动画结束后可隐藏或禁用交互

## 角色分工设计

四个角色保留现有视觉关系，但动作分工明确：

- 黄色角色：主拉角色之一
- 黑色角色：主拉角色之一
- 紫色角色：轻微跟随，不做主拉
- 橙色角色：轻微跟随，不做主拉

主拉角色在动画中需要具备三种状态：

- `idle`：正常站姿
- `pulling`：前倾、手臂伸出、身体受力
- `release`：拉开结束后轻微回弹跳回 `idle`

跟随角色只做轻微位移或倾斜，避免画面过乱。

## 动画节奏设计

完整时间线如下：

### 1. 静止建立画面

- 时长：`0.00s - 0.35s`
- 画面为全屏插画前景
- 用户先感知角色与品牌视觉

### 2. 两个主拉角色蓄力

- 时长：`0.35s - 0.60s`
- 黄色与黑色角色前倾
- 手臂伸向右侧边界
- 身体出现轻微压缩和受力感

### 3. 从最右边往左拉开前景层

- 时长：`0.60s - 1.10s`
- 右侧前景边界从最右向左收起
- 最终停在 `50 / 50`
- 紫色与橙色角色只做轻微跟随位移

### 4. 登录表单露出与淡入

- 时长：`0.80s - 1.25s`
- 表单区在拉开过程中被露出
- 表单标题、输入框、按钮做轻微淡入和上移
- 表单动画不应抢过拉开动作的注意力

### 5. 主拉角色跳回原位

- 时长：`1.10s - 1.45s`
- 黄色与黑色角色做一次短促回弹
- 回弹表现为轻微离地或快速回正
- 动画结束后回到现有登录页中的正常姿态

### 6. 进入稳定态

- 时长：`1.45s+`
- overlay 收到左侧 `50%` 对齐位置后，立即禁用交互，并用极短淡出或直接隐藏的方式交给下层最终态接管
- 页面进入正常可交互状态
- 现有眨眼、眼球跟随、输入联动继续工作

## GSAP 实现设计

使用 `GSAP timeline` 串联整个入场过程。

核心原则：

- 一个主时间线管理全部入场步骤
- 用 timeline 而不是多个 `delay` 分散控制
- 每一段动作都可独立调时长和 easing

建议时间线结构：

1. `set()` 初始态
2. `to()` 主拉角色进入 `pulling`
3. `to()` overlay 的右边界向左收起
4. `fromTo()` 表单内容淡入
5. `to()` 主拉角色进入 `release`
6. `set()` 或完成回调进入稳定态

建议 easing：

- 拉开动作：`power3.inOut`
- 表单淡入：`power2.out`
- 跳回原位：`back.out(1.4)` 或略克制的 `power2.out`

## 前景收起实现方式

推荐优先顺序如下：

### 首选：`clip-path`

用 `clip-path: inset(...)` 或等价遮罩控制 overlay 的可见区域，让右边界从最右侧向左收起。

优点：

- 最符合“右边界被拉开”的语义
- 不需要整体平移整个前景层
- 容易停在准确的 50 / 50

风险：

- 需要确认当前目标浏览器对动画中的 `clip-path` 表现稳定

### 备选：遮罩宽度

通过一个绝对定位的前景容器控制宽度，从 `100%` 收到 `50%`。

优点：

- 更稳

缺点：

- 边界表现力稍弱

不采用：

- 直接 `translateX` 整个前景层，因为不符合动作定义

## 状态管理设计

建议新增一次性入场状态，而不污染现有业务状态：

- `hasPlayedEntranceAnimation: boolean`
- `isEntranceAnimating: boolean`

用途：

- 控制动画仅在页面首次进入时播放一次
- 动画期间可控制 overlay 层可见性和交互性

状态优先在登录页组件内部维护，除非后续确认需要跨页面记忆。

## 响应式与降级

### 桌面端

- 目标是严格 `50 / 50`
- 两个主拉角色靠近右边界，动作清晰可见

### 移动端

- 不强行复刻桌面端横向拉幕布效果
- 可以降级为更简单的上层前景收起或淡出
- 最终仍保持移动端合理的上下布局

### Reduced Motion

如果检测到 `prefers-reduced-motion: reduce`：

- 直接显示最终态
- 不播放强动作入场动画
- 保留必要的轻量交互

## 风险与边界

### 风险 1：与现有角色交互逻辑冲突

当前角色已有眼睛跟随、眨眼、输入态联动。入场动画需要避免在动画未结束时触发这些状态冲突。

处理：

- 动画期间临时锁定角色的交互态
- 动画结束后再恢复现有联动

### 风险 2：用户已有对登录页代码的本地修改

[src/views/login/index.vue](/Users/guitarxiaohe/Desktop/xiaoheCode/sprintboot/xiaoheDOM/src/views/login/index.vue) 当前工作区已有未提交修改。

处理：

- 实施前需要先完整阅读现有变更
- 修改时只叠加入场动画，不覆盖已有用户改动

### 风险 3：移动端横向拉开表现不自然

处理：

- 移动端采用简化版时间线
- 重点保留“前景收起后表单显现”的语义，不强行复制桌面表现

## 验证标准

功能验收通过需满足：

1. 登录页首屏先显示全屏插画前景
2. 黄色与黑色两个角色一起发力拉开右侧前景
3. 前景从最右侧向左收起，而不是整层平移

9. reduced motion 下可直接进入最终态
10. 移动端不会出现明显错位或不可用
